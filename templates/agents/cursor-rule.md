# Running and testing changes

At the start of any coding task, before your first edit, run `{{command}} guide` from this folder and follow what it prints. Run it again before you build, start, debug or test services, read their logs, or hand work to the user for testing.

If this folder is the main checkout (`{{repo}}`), other agents share it. Create your own worktree with `{{command}} new <task-name>` before changing anything.

Changes run in an isolated lane on top of one shared baseline stack. Never start the whole stack yourself, and never run `docker compose` against the project's compose files.
